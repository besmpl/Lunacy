# Cycle 19 ADHD — strategy overhead versus useful delivery

## Brief

The problem is whether Golden can remove genuinely unnecessary strategy work while preserving exact routing, worker authorship, source custody, correctness, required checks, independent acceptance, and separate release authority. The reframe is source-grounded: distinguish a mandatory stage that changes a decision or catches a material defect from execution friction, duplicated framing, or an unproven value claim. This is the complete five-frame, 30-idea run; the current cycle still obeys the full Golden procedure.

## Converge

- **★ assumption-5 — Evidence-triggered, question-scoped advice** `[N7 V7 F9 W7.5]`: strongest fit because it tests whether advice answers a live uncertainty rather than being ceremonial, while retaining the existing downstream route once entered. It remains only a hypothesis: no historical counterfactual shows that an absent advice call would have been unnecessary or safe.
- **markets-6 — Risk-band standing orders** `[N7 V7 F8 W7.25]`: plausible reuse for recurring low-risk shapes with repricing signals, but current records do not establish a recurring shape, safe band, or no quality displacement.
- **assumption-1 — Decision-boundary slices** `[N7 V6 F8 W6.85]`: potentially proportional to uncertainty instead of request size, but coupled slices and required full-route stages make the marginal saving unproven.

### Traps and rejected mechanisms

- Fixed-layout/typed packets, immutable snapshot pointers, reduction bitmaps, microcode, or any new handoff schema: current exact adopted-roadmap reference, TASK/report contract, and source custody already cover the handoff; a new representation adds ceremony.
- Dirty-bit invalidation, evidence liquidity pools, standing ledgers, prediction markets, or replay packs: these add runtime/state or rely on unvalidated risk estimates, contrary to the guidance-only boundary.
- Mandatory recovery envelopes, rerun/fallback/split rules, failure maps, and typed returns: existing targeted repair, `DECISION_REQUIRED`, finite recovery, and acceptance rules already provide conditional handling; making them mandatory can narrow judgment and spend recovery prematurely.
- “Exercise verification only when touched,” implementation-before-design probes, executable ADHD probes, or prewritten acceptance-oracle machinery: they defer or duplicate required evidence, add effects, or conflict with current stage/authority contracts.
- All proposed Focus-1/2/3 mechanisms are not adopted. Focus 1’s historical no-op labels cannot prove the absent-adviser counterfactual and its advice trigger is future behavior, not a current waiver. Focus 2’s exact-routing language conflicts with replacing the fresh strategy and must not be used to fake full ADHD. Focus 3’s parent merge violates worker authorship and its substituted focus conflicts with the one-seed-per-focus contract.

## Focus

### Focus 1 — Evidence-triggered, question-scoped advice

**Sketch.** Golden begins with a bounded local evidence pass and compact TASK, rather than unconditionally asking Astra for advice. That pass names a live question only when it finds ambiguity, conflicting constraints, a concrete failure, or a non-routine decision; otherwise no advice call is made. When a question exists, the parent sends only that question and relevant evidence to targeted advice, which remains advisory and does not own implementation. The result enters the existing 5×6 isolated ADHD → all-30 scoring → three-fresh focus → Luna/high source-checked design → parent adoption → coherent implementation → independent acceptance route, with authorship, source custody, correctness, tests, and release authority unchanged. A later failure can summon advice at the failing decision seam without restarting unrelated upstream work. Offline replay compares removed advice calls with decision changes, caught risks, rework, and acceptance outcomes, making the simplification falsifiable.

**Load-bearing risk.** Local evidence can look coherent while hiding a cross-cutting constraint, and a subjective trigger could become a loophole for suppressing useful advice. Calibrate the trigger against retrospective routine, ambiguous, and failure cases, checking specifically for escaped defects or acceptance rework.

**First concrete step.** Mine recent Golden runs and label each advice call as decision-changing, risk-finding, or no-op; use the results to draft the conditional Markdown branch and a small offline replay set before changing guidance.

**Child ideas.** Failure-seam interrupt; decision-delta advice; evidence-maturity ladder; counterfactual replay; question stop-condition.

### Focus 2 — Risk-band standing orders

**Sketch.** Future Golden guidance could treat a previously accepted, low-risk task shape as a standing order that preselects the same route and reuses still-valid evidence instead of reopening equivalent strategy discovery. The task still follows exact Golden routing and preserves worker authorship, source custody, correctness checks, required tests, independent acceptance, and separate release authority; each stage validates the order rather than regenerating identical work. New dependencies, changed requirements, failed tests, acceptance disagreement, or prior repairs reprice the shape into scrutiny and require fresh strategy work. The savings are falsifiable by comparing strategy-stage effort and defect or rollback rates for repeated shapes before and after adoption, without adding runtime state or a ledger.

**Load-bearing risk.** A stale or overly broad risk-band classification could normalize hidden requirement drift and suppress the scrutiny needed to catch it.

**First concrete step.** Define one narrow recurring task shape and write a guidance-only standing-order template with explicit expiry and repricing signals, then test it against several prior Golden runs.

**Child ideas.** Evidence freshness window; failure-signal taxonomy; seller-side tactic cards; neighboring-shape equivalence only after boundary evidence.

### Focus 3 — Decision-boundary packets

**Sketch.** At the advice boundary, split the request into minimal uncertainty slices, each with a decision question, owned files or contracts, evidence, and an acceptance condition; deterministic glue remains shared context. The exact Astra → isolated ADHD → all-30 scoring → three-focus → Luna source-check → parent adoption → implementation → independent acceptance route still runs, with every required worker retaining authorship. Workers resolve slice-specific uncertainty and reference locked decisions instead of restating or rereading the whole request, while dependency edges force coupled slices to travel together. Parent adoption merges the slice decisions into one coherent design, and acceptance checks both slice criteria and explicit cross-slice invariants. Pilot this on one routine and one coupled task, comparing prose volume, repeated evidence reads, contradictions, rework, tests, and acceptance results against the current route. Keep the guidance only if duplication or rework falls without reducing decision quality or coverage.

**Load-bearing risk.** Incorrect slicing can hide coupling and lock a locally plausible but globally inconsistent decision; if discovering dependencies requires whole-request rereading, the proposed savings disappear.

**First concrete step.** Run a shadow comparison on representative routine and cross-cutting tasks by manually adding a slice manifest to the existing TASK, then record repeated context or evidence work, contradictions, rework, and acceptance coverage before changing the Markdown guidance.

**Child ideas.** Connected-component routing; evidence capsules; adversarial focus; acceptance-first slicing.

**Wildcard (worker-authored).** What if Golden's true unit is not an uncertainty slice but a predicted acceptance failure, with strategy organized around proving or disproving those failure modes before expanding into broader ideation?
