# Lunacy Golden

Treat invocation of `$lunacy-native:golden`, or an explicit request for Golden,
with any outcome as selection of the Golden workflow for that outcome—even
when it is a known implementation rather than strategy discovery. If the user
gives no task, ask what they want done; do not invent a project or restart a
previous goal.

Read and follow the shared [Lunacy native contract](../lunacy/SKILL.md) and canonical [Golden workflow](../lunacy/orchestrator/IMPROVEMENT.md). Apply those references progressively rather than duplicating their rules here. Lunacy can handle a newly authorized, scoped task in an existing repository when current authority and ownership/effect checks permit it; “new” describes the work, not the repository's age. A new task, filename, or installation does not migrate existing or provenance-uncertain work, which retains its original contract and owner.

For adopted large delivery read the shared [ready-work parallel policy](../lunacy/orchestrator/PLANNING.md#ready-work-parallel-delivery) and use Lunacy's [native dispatch recipe](../lunacy/SKILL.md#native-dispatch-recipe) to prepare packets, launch safe waves, record handles, and refill on events. The recipe does not change ADHD's five breadth-worker and three focus-worker stage counts or permit nested spawning. Small or coupled work still has one coherent owner.

The shared [task-local dispatch mode and worker limit](../lunacy/orchestrator/PLANNING.md#dispatch-modes-and-wave-protocol)
also apply to Golden. With adequate observed room, launch all five sealed breadth
assignments before a completion wait, and likewise all three focus assignments.
A lower explicit worker limit changes only simultaneous occupancy: launch
cap-sized waves until the same five and three required outputs settle. It does
not skip workers, score early, mix stages, or authorize a new Golden cycle.

Before planning dispatch, honor task-scoped worker choices under [Worker model selection](../lunacy/orchestrator/WORKER-MODELS.md). `choose workers` selects delivery `bulk` and `judgment` only; both default to `gpt-6-luna / max`. For a hard delivery, diagnosis, or discriminating-verification assignment, a clear affirmative request such as `use Sol medium` opts only `judgment` into `gpt-5.6-sol / medium`; record it before a new assignment. Quoted, negated, hypothetical, or incidental mentions are not authorization. Difficulty or worker failure never enables it, and it does not change bulk, the parent, ADHD, consultation, or a live assignment. Golden has distinct ADHD selectors. `choose ADHD workers`, or `ADHD workers: gpt-6-astra / low`, binds one uniform model/effort pair. The opt-in staged form `ADHD stages: breadth gpt-6-luna / max; focus gpt-6-astra / low` binds exact breadth and focus pairs; the literals are examples, not fixed routes. Omission keeps uniform `gpt-6-luna / max`. Apply the canonical [ADHD worker selection, route, and sealing](../lunacy/orchestrator/IMPROVEMENT.md) rules before divergence. Resolve both stage pairs first, preserve stage-specific repair and provocation routing, and block malformed, incomplete, unavailable, unsupported, or conflicting choices without guessing or fallback. A simultaneous uniform selector is allowed only when it exactly equals both stage pairs. These selectors are conversational and do not modify Codex's global model picker.

## Golden execution card

1. Frame the authorized outcome, constraints, preserved behavior, acceptance evidence, and separate release authority.
2. Obtain the task-selected consultation, then run the available ADHD skill with its required isolation, five breadth workers aiming for six distinct ideas each, scoring every actual idea without padding, trap removal, and three fresh one-seed focus workers when three viable seeds exist, using the applicable sealed stage pair.
3. Selected ADHD workers own candidate proposals, deepening material, output
repair, and final provocation; `gpt-6-luna` / `max` owns substantive evidence by default
reconciliation, solution revision, design, and roadmap prose. The parent owns
workflow judgment and acceptance: Astra in its parent role may frame criteria,
select, reject, adopt in the existing `TASK.md`, and accept without authoring
substantive Golden or ADHD-worker output. Astra in an adviser role supplies
bounded advice and evidence only and has no authority to select, reject, adopt,
or accept. An Astra-routed ADHD worker is the selected-worker exception and may
author only its assigned ADHD material.
4. Use the shared orchestrator guidance already linked in this skill for direct adopted-roadmap delivery to the outcome-owning worker; ordinary pre-FINAL repair stays with that owner, while substantive post-FINAL repair uses the canonical new-assignment/new-report handoff.

The selected ADHD binding—not the later Luna route—authors fresh isolated ADHD generator/deepener proposals, output repair, and final provocation. Breadth repair uses the breadth pair; focus repair and final provocation use the focus pair. A new unbound task defaults to uniform `gpt-6-luna` / `max`; exact task-local choices remain binding for the entire round. After ADHD, the separately sealed design worker defaults to `gpt-6-luna` / `max` for substantive evidence reconciliation, solution revision, design, and roadmap prose. Score every actual breadth idea after all branches settle; do not pad a settled worker's valid short array to reach six. Give each fresh focus worker the common brief and instructions plus its one selected seed, without the full pool or scores. Include a `provocation` JSON field in the first focus worker's assignment, preserving its JSON-only response, so that worker authors it without another call. Keep authorized full source/evidence accessible with provenance, freshness, and custody; do not require wholesale packet copying. A mid-round pair change must never mix earlier generators with newly selected deepeners; after settlement, changed bindings require a newly authorized full ADHD round. Shared routing supplies consultation selection, custody, evidence, cache, acceptance, and finite-stage rules; quota pressure never permits silent fallback, and work whose effects are unknown is not replayed. An ambiguous dispatch return forbids replay or replacement; a known live handle uses its supported blocking wait or authorized cancellation and effect settlement. Missing or malformed strategy output pauses dependent advancement; a settled valid short idea array is not missing output. Fewer than three viable survivors is an incomplete focus, not a padded winner; malformed output is an output defect, not negative idea evidence. Use the shared finite dispositions `no-worthy-opportunity`, `unresolved-evidence`, and `review-deferred` truthfully. Follow the shared rejection handoff for local Luna repair versus a newly authorized full ADHD round when a causal mechanism fails.

Source-only and design-only authority delivers only its authorized artifacts.
Ordinary Lunacy follows the shared worker defaults above, and this shortcut does
not alter global/model configuration, create a scheduler or ledger, grant
publication permission, or invent a task. Explicit Golden selection is required
for this workflow; a task-free invocation asks what the user wants rather than
restarting prior work.

When the user explicitly requests token or cost metrics, the optional shared
[offline usage report](../lunacy/orchestrator/USAGE-METRICS.md) can summarize
caller-selected receipts. Do not run it automatically or treat its dated
API-equivalent scenarios as subscription billing or complete Golden coverage.
