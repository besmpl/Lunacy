# Adaptive deliberation operator contract

Lunacy v1 contains one private, bounded decision-settlement capability. It
automatically chooses a cognitive gear while the parent authors a Plan; it is
not a user-selected worker mode, a second scheduler, or a second authority
path. **The package/runtime rollout is disabled by default.** Building or deploying
the managed runtime does not create an ambient cohort. The installed Lunacy
operator profile defaults plain `$lunacy` Plan authorship to exactly one
canonical typed `AUTO` request. Explicit `DIRECT` and explicit `EXPLORE` remain
authoritative overrides. AUTO never selects Explore, and a complete Plan takes
the physically isolated zero-call Direct branch. At an eligible unresolved
named discriminator, AUTO selects the reviewed D3 `automatic-focus` policy
once at the pre-Plan host-composition boundary; omission or nonconformance
still leaves the managed path disabled/refused.

## One decision, three deterministic gears

Gear selection is deterministic for the sealed decision/evidence/policy
inputs. Explicit Explore direction wins; otherwise proof that only one route
remains selects Direct and another unresolved material discriminator selects
Focus. New installed commands never select Explore implicitly. Historical D4
reader/recovery behavior remains supported but cannot mint new authority.

- **Direct** is a true bypass: no Wave, Report, deliberation budget, managed
  host, or model fan-out is initialized. Ordinary Lunacy execution is
  unchanged.
- **Focus** is exactly two isolated, one-candidate generators followed by one
  critic. It has no deepener. Installed automatic Focus is one-shot: if its
  single Wave does not settle, the host returns exactly one parent decision
  boundary and does not automatically `WIDEN` or start another Wave.
- **Explore** is five isolated generators producing six ideas each, one critic
  over all 30, exactly 3–6 mechanism clusters, trap exclusion, descending
  `35N + 40V + 25F` ranking with deterministic ties, and exactly three
  deepeners for the top three non-traps.

Generators, critic, and deepeners receive only their closed role view. Their
Reports cannot select, write the workspace, launch children or tools, or grant
effects. The parent alone selects or synthesizes a settlement, authors the
complete Plan, adopts authority, handles approvals, and closes gates.

New Waves author exactly `maxModelCalls`, `maxWaveBytes`, `maxRefs`,
`maxResolvedRoleInputBytes`, `maxReportBytes`, and `maxTotalReportBytes`.
Readers still normalize archived decorations. After six-key publication,
rollback is only to an L3a or later compatible reader, never pre-L3 strict-nine.

Effect-denied adaptive work is pinned to the attested `gpt-5.6-luna`/`max`
host profile. Writable managed action remains on its separate attested
`gpt-5.6-sol`/`high` boundary. Direct/manual routes are separate again. A
missing or unsupported exact route blocks; no route falls back, substitutes,
or downgrades to another model or effort.

All durable work remains in the existing RunKernel, store, journal, outbox,
epochs, decision tokens, publication leases, and authority CAS. Wave v2 and
Report v2 are the only deliberation artifacts. Topology and progress are
derived rather than stored in a second manifest or service.

The private decision-inbox convenience path does not add an authority or
scheduler. Only its fresh successful decision CAS may carry a volatile
process-local winner witness into one call of the existing `resumeRun` pump;
replay, conflict, and driverless handling stop at the durable result. A crash
with `PENDING` work therefore uses ordinary restart/resume rather than a
decision-specific recovery protocol.

## Rollout corridor and eligibility

The existing closed rollout policy has one monotonic generation and one mode:

| Rung | Exact mode | Admission |
|---|---|---|
| Off | `disabled` | No managed deliberation; this remains the package/runtime fail-safe default. |
| D0 | `shadow` | Synthetic **and** disposable sealed input only; authority is mechanically denied. |
| D1 | `focus-canary` | One unsettled Focus decision with sealed evidence, static topology, no child delegation, claims, or effects. |
| D2 | `explicit-explore-canary` | D1 Focus plus explicitly requested unsettled Explore. |
| D3 | `automatic-focus` | At most one eligible automatic pre-Plan Focus Wave plus explicit Explore; no implicit Explore. |
| D4 | `automatic-explore` | D3 plus eligible implicit Explore only when open-ended, high-stakes, and openly phrased are all true. |

The D4 row remains a historical/internal reader contract. Current installed
admission is explicit-only for Explore even when that retained policy spelling
is read.

Every non-Direct rung also requires the exact effect-denied capability,
one decision key, closed static topology, sealed evidence, no claims/effects,
and no child delegation. Shadow output is diagnostic only: its origin remains
non-authoritative even if a later policy generation selects another mode.
Canary eligibility never makes a settled decision unresolved and never grants
authority from a metric.

The native managed profile must attest the Codex image, Luna/max arguments,
role schema, minimal runtime inputs, endpoint policy, bounded in-process
transport, OS read isolation, per-attempt scratch, process-tree teardown, and
receipt/transport/authority anchors. Unsupported platforms or an unavailable,
drifted, or over-broad capability refuse before provider entry. Path secrecy,
permissions, prompt promises, direct network access, or a fallback host are
not substitutes.

## Installed D3 host profile

D3 is an operator-owned host-composition choice, not a runtime default, global
flag, deployment-manifest field, or second control plane. Plain `$lunacy` Plan
authorship defaults to exactly one canonical typed `AUTO` request; explicit
`DIRECT` and explicit `EXPLORE` remain authoritative overrides. AUTO never
selects Explore, and a complete Plan takes the physically isolated zero-call
Direct branch. The installed profile composes automatic Focus at most once for
a new eligible managed run: only
before the acceptance pointer/Plan is sealed, before the first implementation
spawn, and when no automatic Focus Wave or accepted rollout projection already
exists. That one pre-Plan composition passes:

```js
const policy = createManagedRolloutPolicy({
  generation: 1,
  mode: 'automatic-focus',
});
```

The profile binds that policy only with the exact attested effect-denied
Luna/max capability, a validated Wave and role policy, one unsettled decision
key, closed static topology, sealed evidence, no claims/effects, and no child
delegation. Direct remains a zero-fan-out bypass. D3 admits automatic Focus and
explicitly requested unsettled Explore only; it never admits implicit Explore.
The parent remains the sole settlement, complete-Plan authorship/adoption, and
gate authority.

## Installed pre-Plan resolver

The only installed selection/authorship seam is the verified private
`"$NODE" runtime/bridge.mjs resolve-plan` route. The trusted parent passes one canonical closed `DIRECT | AUTO | EXPLORE` request. Focus and Explore additionally carry exact deliberation and rollout policy documents. The adapter
does not inspect free-form user text and performs selection exactly once.
Direct returns the complete Plan with no Wave, managed options, lease, or
provider call. Focus and Explore validate the authored Wave and enter the
existing managed START path within that same process.

For each current Explore invocation, the adapter mints one private process-local
authorization and composition/kernel consume it once. Its exact binding covers
the intent Ref, authority digest, Wave digest, run and phase, and rollout policy
digest. It is never serialized or persisted. `explicitExplore`, Report text,
metrics, gate results, and prior requests remain non-authoritative.

After that one automatic Wave, the host never automatically composes another
Focus or `WIDEN`s from its Reports. Gates, repair, worker completion, resume,
rollout transitions, and an existing rollout-bearing run are all ineligible
entry points. If the Wave does not settle, stop automatic deliberation and
return exactly one parent decision boundary. A user may still explicitly ask
for ADHD/Explore; that explicit path is separate and never inferred from the
automatic Focus result or boundary.

If proof of new-run eligibility, capability, Wave, role policy, or other closed
eligibility facts is absent, malformed, drifted, or unavailable, do not guess
or partially compose a managed run: omit the managed composition inputs or let
the existing validator refuse them. The package/runtime supplies no ambient D3
policy and no fallback route. Do not add a persisted one-shot flag, controller,
parser, event, state key, or lifecycle API: the installed host owns this
pre-Plan admission rule.

## Verify the D3 candidate

From the canonical source checkout, these commands validate the operator
surface and exercise a disposable deployment; they do not touch an installed
skill or change rollout policy:

```sh
NODE="$(command -v node)"
CODEX_HOME="${CODEX_HOME:-$HOME/.codex}"
npm run build
python3 "$CODEX_HOME/skills/.system/skill-creator/scripts/quick_validate.py" .
TARGET="$(mktemp -d)"
trap 'rm -rf "$TARGET"' EXIT
"$NODE" tools/deploy-skill.mjs --target "$TARGET"
"$NODE" tools/deploy-skill.mjs --target "$TARGET" --check
```

Before considering any non-disabled generation, also run the focused rollout
matrix and the actual installed Codex capability smoke on the candidate source:

```sh
node --test test/p4-rollout.test.js
LUNACY_ACTUAL_CODEX_SMOKE=1 node --test \
  --test-name-pattern='actual installed Codex Luna/max' test/p4-rollout.test.js
```

The profile above is the complete promotion action. Use the existing
`createManagedRolloutPolicy()` constructor; do not hand-edit MachineState,
Wave/Report bytes, projections, or deployment manifests. The package/runtime
still has no ambient rollout default, global flag, or automatic promotion.

## Kill, revoke, and roll back

For an immediate composition stop, set the existing `managedKillSwitch: true`
before the next kernel call. For durable revocation, publish a strictly newer
closed rollout policy whose mode is `disabled`, then resume through the normal
RunKernel boundary. Reusing a generation, editing the persisted projection, or
deleting evidence is invalid. A newer disabled generation blocks new admission
and existing managed resume before more work is launched.

```js
const revoked = createManagedRolloutPolicy({
  generation: previous.generation + 1,
  mode: 'disabled',
});
```

Preserve the journal, policy, Wave, Report, settlement, receipt, transport,
anchor, and lease evidence. For an effect incident, also advance the existing
writer-fence epoch through its authoritative path. An existing run that has
entered automatic Focus remains ineligible for automatic re-entry, including
after revocation; never rewrite or downgrade old state. Deployment rollback is
independent and uses the attested restore/redeploy procedure in
[`../docs/INSTALL.md`](../docs/INSTALL.md); it does not itself alter a cohort.

## Diagnostics and recovery

Managed metrics are bounded, saturating, in-process diagnostics: proposal and
admission/refusal/kill counts, parent outcomes, zero-count safety invariants,
calls/tokens/bytes/Refs, and latency buckets. They may be lost on restart and
must never select a gear, promote a cohort, consume a decision, or authorize an
effect. Treat any nonzero fallback, authority-escape, stale-adoption,
ceiling-overrun, authoritative-deletion, duplicate-entry, or partial-promotion
counter as a stop-and-investigate signal, not an automatic policy input.

Timeout, cancellation, crash, or ambiguous provider entry cannot publish
`UNKNOWN` until the owned process tree has exited, private scratch is removed,
and teardown evidence is bound. Recovery never re-enters that attempt epoch;
the complete reservation remains charged and late output is inert. The
installed automatic D3 host does not retry or recompose on recovery; it returns
the single parent decision boundary after teardown. If capability, budget,
sealed input, transport, or recovery proof is missing, the run blocks or
returns parent-required handling with no partial promotion.
Use the read-only capsule described in [`../docs/RECOVERY.md`](../docs/RECOVERY.md)
for bounded diagnosis; never repair private state from the capsule.
