P3 — R3 reader/writer and resolver core. One owner implements union-tolerant durable readers, context-strict current admission, exact new writers, and the single `resolvePrePlan` production seam. Gate: collision/replay/exactness matrix plus broad check.

P4 — R4 installed host resolver and doctrine. One owner implements the private verified `resolve-plan` bridge route, ephemeral exact Explore authorization, composition/admission binding, docs, and deployed tracked-only smokes. Gate: intent/cutoff/authorization matrix plus broad check.

Each phase is an independently reversible accepted product boundary, not a progress/proof milestone. R0 is folded into P1 because it is acceptance proof for routing rather than a standalone product release. P1-P4 are serialized because they share runtime interpretation.
